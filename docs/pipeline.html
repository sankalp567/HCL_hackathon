1 · Offline extraction: keep tables, charts and KPI tiles as data

owner: member A · runs once on the sustain GPU server

Plain text extraction loses structure. Measured this morning: tables flatten, chart labels scramble (TCS’s revenue trend reads “2 67, 0 2 … 1 9 1 , 754” and ₹ comes out as “H”), and KPI tiles lose which number belongs to which label. So every page goes through a layout-aware parser (Docling), the charted metrics are taken from tables, and every number is checked against the page’s own text. Charts and tiles get an optional extra pass with free models. No paid API anywhere.

Both parsers fail on TCS’s designed pages, so those go through the vision pass. About 200 pages are statements and notes (clean tables); 8 TCS pages are letter-spaced; 10 are image-only.

Why this split

  • Text-layer numbers are exact. Where the parser can read a table, its numbers come straight from the PDF, character for character. A model is only needed where the text layer fails.
  • Charts are optional. Revenue, margin, headcount, attrition and geography also appear in statement, MD&A or BRSR tables. A chart value read by a model is used only after a person signs it off.
  • Tools, all free. Docling (MIT, IBM): layout model, TableFormer tables, figure detection, page + box for every item, on the sustain GPUs. PyMuPDF4LLM (tested above) is the fast fallback. Extras: RapidOCR (bundled with Docling) and IBM’s open Granite Vision chart model.
  • Run once, share the result. Minutes on the GPU. facts.db is committed, so teammates need no GPU and no parser.

2 · The fact store: one SQLite file that every later layer reads

owner: member A (schema, loader) · read by B, C and D

Numbers are stored as data, not text: one row per number in long format, like XBRL (company · metric · year · value · unit), each with the exact place it came from. The chart, the Q&A and the page viewer all read the same checked rows.

How each later layer uses it

Chart (R1)

SELECT company, fy, value, page_no, bbox
FROM facts WHERE metric = 'revenue'
  AND basis = 'consolidated' AND status = 'verified'

Q&A (R2)

Three lookups: query_facts(company, metric, fy) · get_table(element_id) · search_passages(query, company). Numbers come from facts and table cells; descriptive answers are spans from passages.

Page viewer

The bbox highlights the exact table cell or chart bar, not just a sentence.

Evaluation

Numeric test questions are graded against facts; a report counts how many values agree across 2+ places.

Built once on the GPU server and committed as data/facts.db with a JSON export. Everyone else only reads it.

4 · Ask the reports (R2): answer with citations, or refuse

owner: member B · POST /api/ask

Four ways to stop and one way to answer. An answer is shown only when every quote it relies on is found in the passage it cites. Every question is logged with the passages, scores and the gate that decided it.

How an answer is built (no LLM, no API)

  • Numeric (“Infosys revenue FY26?”): company, metric and year are detected, and the value is read from facts.db with its page.
  • Comparison (“compare headcount”): one fact per company → a templated sentence with three citations.
  • Descriptive (“HCLTech on GenAI?”): top passages → the QA model picks the span; the sentence around it is shown with its page.
  • Answers are verbatim spans or stored facts, so a citation cannot point to text that isn’t there.

Response of POST /api/ask

{
  "status":  "answered",     // answered | not_found | out_of_scope
  "answer":  "…",
  "citations": [{ "company": "Infosys",
                  "report":  "Integrated Annual Report 2025-26",
                  "page":    <PDF page>,
                  "quote":   "<exact text>",
                  "verified": true }],
  "trace":   { "passages": […], "gate": null,
               "latency_ms": …, "tokens": … }
}

8 · Design decisions, risks and stack

the top 5 decisions feed REPORT.md
1

Page-level provenance, end to end

Passages never cross pages, so every answer and every bar names one PDF page that anyone can open.

2

Keywords first, vectors second

BM25 handles exact terms and figures; embeddings add paraphrases; merged by rank (RRF) with a quota per company so comparisons see all three.

3

Refusal is designed in

A scope guard plus three gates (evidence, abstain, citation check) lead to one honest “Not found in the reports”.

4

Extractive, not generative

Answers are rows from facts.db or exact spans picked by small local models. Nothing is generated, so nothing can be invented; free and offline.

5

Numbers are data, not text

Extracted once into facts.db with unit, FY, page, box and checks. The chart and the Q&A read the same verified facts; no LLM on the chart path.

Assumptions (the brief says: assume, note, go)

  • FY2025-26 = year ending 31 March 2026, the latest report of each company.
  • Consolidated figures, ₹ crore, unless the chart says otherwise.
  • Citations use PDF page numbers.

Out of scope (from the brief)

Share-price prediction · investment advice · news, broker notes and websites beyond the reports.

Questions the judges are likely to ask, and our short answers

Why no large language model?Free compute only. Extractive answers are verbatim spans or stored facts, so they cannot be invented; the brief allows keyword search plus extractive answers.
How do you know a citation is right?Gate 7 checks by code that the span is on the cited page and numbers match facts.db; chart values also get a person’s sign-off.
Why does HCLTech show EBIT margin?Its report never says “operating margin”; we keep its own term and say so under the chart.
How do you read numbers inside charts?The charted metrics come from tables. The optional chart pass (free Granite Vision model) feeds values only after a person checks them.
How did you use AI coding assistants?Disclosed in REPORT.md: what was generated, and how each part was checked (tests, the eval set, reading the cited pages).
